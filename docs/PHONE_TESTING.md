# Doodhee phone testing

## Current setup

Updated on 14 November 2026 after investigating the phone's Send code timeout.

- The old APK contained `http://10.0.2.2:18080`, which is for an Android emulator.
- The original Public Gateway listened only on `127.0.0.1`, which a Wi-Fi phone cannot reach directly.
- The computer's current Wi-Fi address is `192.168.29.127`.
- The rebuilt APK uses **`http://192.168.29.127:18080`**.
- A Public Gateway instance is currently running on that Wi-Fi address. It uses the existing backend code, database and role checks. Existing local public/admin processes were preserved.
- The user confirmed that opening `http://192.168.29.127:18080/health/ready` on the phone shows `ok`.

## Install and log in

1. Keep the phone and computer connected to the same Wi-Fi. Keep the computer and gateway running.
2. Install `artifacts/android/doodhee-wifi-v1.1.1-arm64.apk` over the previous app. It uses the same development signing certificate and contains the complete Milkman/customer delivery update.
3. Open Doodhee. Existing users choose **Sign in** and enter only their phone number. First-time users choose **New account**, select Buyer or Milkman, and enter their name and phone number.
4. With the current `TESTING_MODE=true` setting, the new app shows the six-digit code directly in a **Testing OTP** panel. Enter it into the verification field. See [testing mode](TESTING_MODE.md) to hide it later. SMS delivery is not configured.

When testing display is disabled, watch new OTP log entries with this command before requesting a code:

```bash
tail -n 0 -F /tmp/doodhee-public-lan-dev.log | rg --line-buffered '"challenge_code"'
```

Use the new six-digit `challenge_code` generated by your request. A request expires after five minutes; wait at least 30 seconds before requesting another code.

The Public Gateway for buyer/seller login does not use the admin's authenticator code. Admin login remains on the separate admin website/gateway.

## Restart after closing the server

The current listeners run as user-managed services. To reload the current `.env` settings:

```bash
systemctl --user restart doodhee-public-gateway doodhee-admin-gateway doodhee-public-wifi
```

After a reboot, or when the managed services have been stopped, run this from `/home/hp/WorkSpace/doodhee` in a terminal:

```bash
LAN_IP=192.168.29.127 make public-lan
```

Leave that terminal open. Its OTP codes appear directly in the terminal. The database must also be running (`make db-up` if needed). Existing local gateways can keep running.

The Wi-Fi IP can change after switching networks or renewing DHCP. Check it with `ip -4 -brief address`. If it changes, use the new address for the listener and rebuild:

```bash
PUBLIC_API_URL=http://192.168.29.127:18080 make android-share
```

Replace the IP in both commands with the actual new address. Sharing builds now require `PUBLIC_API_URL` explicitly, preventing an accidental fallback to an emulator-only URL. For use outside this Wi-Fi, a deployed backend and its real URL are needed.
